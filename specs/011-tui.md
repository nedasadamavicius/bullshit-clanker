# 011 — TUI

Build-order steps 1, 3, 4 (the operator's half). Depends on 006, 009, 010.

Read [`000-overview.md`](000-overview.md) first. Holds **I4** — the write permit lives
here.

## Goal

`PRODUCT.md`: "TUI v1: scrollback, input, tool trace, patch pane. Ugly is fine." Plus the
accept keybind that is the only way a patch reaches the tree.

## Scope

In: `Hatch.TUI` (Ratatouille app), layout, keybinds, event subscription, the apply/reject
keypress path.

Out: everything it displays.

## Design

Add dep `{:ratatouille, "~> 0.5"}` (overview §2 decision 2, including the raw-ANSI
fallback clause).

### Wiring

`Hatch.CLI.main/1` (001) ends by starting a board job and running the TUI event loop
instead of printing-and-exiting. The TUI subscribes to `Hatch.Events.topic(session_id)`
and converts `{:hatch_event, e}` messages into model updates.

Ratatouille's runtime delivers `{:event, %ExTermbox.Event{}}`; PubSub messages arrive as
plain messages — handle both in `update/2`.

### Layout

```
┌──────────────────────────────┬───────────────────┐
│ transcript (scrollback)      │ tool trace        │
│ user / assistant / notes     │ kb.search ok 12ms │
│                              │ kb.read  ok       │
├──────────────────────────────┴───────────────────┤
│ patch pane — visible only when a proposal pends  │
│ nearest: mk2   deltas: 4   citations: 3          │
│ + diff, scrollable, citations listed under it    │
├──────────────────────────────────────────────────┤
│ > input                                          │
├──────────────────────────────────────────────────┤
│ kb=./kb boards=12 tree=./overlay model=… [build] │
└──────────────────────────────────────────────────┘
```

- Transcript: user lines, assistant text (streaming, appended per `:assistant_delta`),
  system notes (applied/rejected/build), errors. Wrapped to the pane, scrollable.
- Tool trace: one line per tool call — name, ok/err, duration, one-line summary. Never
  the payload.
- Patch pane: appears on `:proposal`, disappears on apply/reject/supersede. Shows nearest
  board id, the delta table (`KB.Delta.render/1`), the **citations with their claims**,
  and the diff. When a proposal is `:proposal_invalid`, show the reasons here instead —
  the operator should see the model failing the citation check, not just silence.
- Status bar: kb path, board count, tree path or `no tree`, model name, build state
  (`idle` / `building…` / `exit 0` / `exit 2` / `timed out` / `no toolchain`), and a
  `pending patch` indicator. Never the API key.

### Modes and keybinds

Two modes, because single-letter keybinds and a text input cannot share a keyboard.

**Insert** (default): typing goes to the input. `Enter` sends (`Session.send_message/2`),
`Esc` → normal, `Ctrl+C` quits.

**Normal**:

| Key | Action |
|---|---|
| `i` | insert mode |
| `j`/`k`, `PgUp`/`PgDn` | scroll focused pane |
| `Tab` | cycle focus: transcript → trace → patch |
| `a` | **accept** the pending proposal |
| `r` | reject the pending proposal |
| `b` | `tamago.build` on demand |
| `c` | cancel the running turn |
| `q`, `Ctrl+C` | quit |

`a` with no pending proposal is a no-op with a status-bar hint, not an error.

### The accept path (I4)

`a` in normal mode with a pending proposal, **and the patch pane focused or the proposal
visible**:

1. Show an inline confirm line: `apply <n> files from proposal p_ab12? [y/N]`. A second
   key is required — `a` alone must not write. Any key but `y` cancels.
2. On `y`: `permit = Hatch.Permit.mint(proposal_id, session_id)` — **the only call site in
   the codebase** (009 acceptance 9) — then `Hatch.Patch.Apply.apply_patch(proposal, permit)`
   via the `:patch_applier` seam, run in a `Task` so a slow `git apply` does not freeze
   the UI.
3. Result → `Session.note_applied/3` (or an error note), status bar update, patch pane
   closes on success and stays open with the conflict message on failure.

`r` prompts for an optional one-line reason, then `Session.note_rejected/3`.

No auto-apply. No "apply and build". No keybind that applies without the confirm step.
No mouse.

### Robustness

- The TUI must survive the session dying: on `:DOWN` from the session, show an error line
  and keep the transcript readable. `PRODUCT.md`'s whole point is that the operator's
  context is not lost.
- A 5 MiB patch must not lock rendering: the patch pane renders only the visible window of
  lines.
- Terminal resize re-lays out without crashing.
- On quit, the port/worker children are terminated (the board job supervisor is stopped),
  so no `go build` is left running.

## Acceptance criteria

Rendering is tested as a pure function of state — do **not** try to drive termbox in CI.

1. `Hatch.TUI.Model.update/2` is pure: given a state and a `{:hatch_event, e}` for every
   event type in overview §6, it returns the expected state. One test per event type.
2. A `:proposal` event opens the patch pane with the delta table, citations (path +
   claim), and diff; `:proposal_invalid` shows the reasons.
3. `a` in normal mode sets a confirm-pending state and mints **no** permit; `y` then mints
   exactly one and calls the applier seam once; any other key cancels and mints none.
   **(I4)**
4. `a` with no pending proposal changes nothing and sets a hint.
5. In insert mode, `a` types the letter `a` and mints nothing. **(the obvious footgun)**
6. `:apply_result, ok: true` closes the patch pane; `ok: false` keeps it and shows the
   conflict text.
7. `:assistant_delta` events append to the last assistant line rather than creating a new
   one per token.
8. `:build_*` events drive the status bar through `building…` → `exit N`; `timed_out`
   renders distinctly.
9. Session `:DOWN` renders an error line and does not crash the update function.
10. The API key appears in no rendered cell — assert over the full rendered view for a
    state containing a config.
11. Quitting stops the board job supervisor (assert the pid is down).

## Test plan

`test/hatch/tui/model_test.exs` covering the table above with the applier and permit
behind the §7 seams. A single smoke test may construct the Ratatouille view tree and
assert it renders to a struct without raising; no terminal is required.

## Constraints

- One TUI library for v1 (overview §2). Do not add a second rendering path, a web UI, or
  a `--json` mode.
- The permit is minted here and nowhere else.
- Ugly is fine. Do not spend the budget on borders.
